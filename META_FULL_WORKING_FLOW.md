# WishFlow Meta / WhatsApp Full Working Flow

This build implements the application side of the production flow:

1. Super Admin creates/configures one WishFlow Meta Developer App in Meta for Developers.
2. Super Admin saves App ID, App Secret, Embedded Signup Configuration ID and Graph API version in WishFlow Admin Settings. App Secret is encrypted in PostgreSQL.
3. Each business owner logs into WishFlow and uses Connect with Meta.
4. WishFlow creates a one-time signup session linked to that logged-in business and opens Meta/Facebook Business Login.
5. Meta returns an authorization code to the HTTPS callback.
6. The backend exchanges the code, discovers the business WABA and Phone Number ID, verifies the number, encrypts the access token, subscribes the WABA where allowed, and syncs real templates.
7. Logout removes only the WishFlow session; the WhatsApp connection remains in PostgreSQL for that business.
8. Automations load credentials by owner/business ID and send with that business's Phone Number ID and decrypted token.

## Important external prerequisite

Meta App ID, App Secret and Embedded Signup Configuration ID are issued by Meta. They cannot be generated by WishFlow code. Use the new **Open Meta for Developers** button in Admin Settings to create/configure the platform app, then paste the issued values into WishFlow.

## Automation-ready requirements

A business is ready when:
- Meta connection status is CONNECTED
- encrypted access token exists
- Phone Number ID exists
- WABA ID exists
- at least one template is APPROVED

The WhatsApp connection screen now shows this readiness explicitly.
